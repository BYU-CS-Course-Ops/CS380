CP7 Checklist

Project / repo

Every stranger who meets a project — a potential contributor, a user, an employer — meets it through the same few files, in the same order: What is this? Can I run it? May I use it? How do I help? What's it like here? Check each item the way that stranger would, not the way you would. You already know everything, and they don't.

1 · READMEREADME.md

  • The first sentence says what it is and who it's for
  • A status line: what works today
  • A quickstart that works, or an honest “not runnable yet” pointing to docs/setup.md
  • Links to CONTRIBUTING; ends with a license line

2 · LicenseLICENSE

  • Exact license text; fields filled in if it has any (MIT, BSD: year and holder)
  • A one-paragraph rationale recorded: why this license for this project, not MIT by reflex

3 · Contributing guideCONTRIBUTING.md

  • Opens with how to get started, not with rules
  • How to pick work, the PR process, review expectations (grown from your git standards); links to docs/setup.md
  • Says what a newcomer should do first

4 · Code of conductCODE_OF_CONDUCT.md

  • Adopted from a standard (Contributor Covenant), not written from scratch
  • A reporting contact you'll check, a response time, and a route for reports about you

5 · Templates + labels.github/

  • Bug template asks for steps to reproduce, expected vs. actual, and environment
  • Feature template asks for the need, the user, and today's workaround
  • PR template checklist pulled from your git standards
  • Labels: bug, enhancement, good first issue, plus your own, created before a form names them (a form skips missing labels)

6 · Setup placeholderdocs/setup.md

The full guide comes once there's code to set up; a stranger follows it in the repo audit.

  • The stack and prerequisites your design already commits to
  • Says setup instructions arrive with the first runnable build
  • Links the issue that tracks writing them

7 · Communication normsdocs/communication-norms.md

  • Where discussion happens
  • Response times you can actually keep ("within a week," not "24/7")
  • Who maintains, and how decisions get made
  • How you'll know which new issues are still waiting for that reply (a label, a board column, a set day: your pick)

8 · Seed issuesIssues tab

  • 2–3 real next-work items, filed through your own templates (a task with no form? use the closest one, or add a task form)

✓ · Ship itCanvas

  • Your review partner read your README and CONTRIBUTING cold on a Stranger's Read sheet, and you acted on it
  • Everything merged to main through reviewed PRs (solo: a written self-review)
  • A cp7 tag pushed; its URL and a photo of the Stranger's Read sheet submitted in Canvas
Where the points are: the two heaviest criteria are Completeness (everything above, substantive) and Newcomer usability (a stranger can tell what this is, where it's going, and how to start helping, from the docs alone), worth 25 each. The same stranger's test comes back in the repo audit, with install and run added.
