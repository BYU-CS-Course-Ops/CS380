Reading the ratings: one High with a spike planned is fine. What sinks projects is unacknowledged High risk. Three Highs and no plan means shrink the scope or pick another idea.

2 · Know / Learn / Avoid, for Idea A — 2 min

Sort what the build takes. Every Avoid you can justify makes the project more feasible. Routing around complexity is a skill, not a cop-out.

SMART = Specific · Measurable · Achievable · Relevant · Timed. "Learn WebSockets" isn't a goal; "two tabs exchange messages through a server I wrote" is — you can tell when it's done.

De-risk moves — pick one for each starred risk

  • Technical / Skill → run a spike; make a learning plan
  • Schedule → cut to a smaller vertical slice
  • Dependency → find a fallback; confirm terms and cost now
  • Adoption → one more real user conversation
  • Maintenance → the boring stack you can own and explain
