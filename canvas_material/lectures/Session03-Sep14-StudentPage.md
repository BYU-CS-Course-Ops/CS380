## Purpose

Today is about the **"open" in open source.** You're still hunting for problems on your own time; in class we start learning what it takes to *found* a project others can see, use, and join — **why** we build in the open, **how** software licenses actually work (and which to pick), and the **governance** choices a founder makes so a project is safe and inviting to contribute to. You'll leave having chosen a license for the project you're imagining.

---

## Learning objectives

By the end of this session, you'll be able to:

1. **Explain the open-source model** and why founding a project in the open is worth it.
2. **Compare the major license families** — permissive (MIT, Apache-2.0) vs. copyleft (GPL, AGPL) — and what they mean in practice.
3. **Choose and justify a license** for a project.
4. **Name the governance choices a founder makes** — visibility, code of conduct, contribution process, communication, decision-making.
5. **Describe the lead-as-sponsor / maintainer role** you'll grow into.

## What we'll do together

Why building in the open is worth it; how to read *any* license (the Permissions / Conditions / Limitations model) with a live tour of choosealicense.com; what strong vs. early-stage project governance looks like; and a group activity where you decide the license and governance for a real project.
